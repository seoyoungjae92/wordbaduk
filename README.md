# wordbaduk — 끝말잇기 대국

바둑 대국의 형식을 빌린 끝말잇기. 토스 **앱인토스** 미니앱으로 낼 것을 전제로 만들었다.

핵심은 하나다. **져줄 줄 아는 AI.**
Play 스토어에 끝말잇기 앱이 28개 넘게 있는데 평점이 3점대다(2.8~3.9, 같은 시장 단어게임은 4.6~4.9).
불만의 정체는 앱 목록에 그대로 드러나 있다 — 「끝말잇기 한방단어」「끝말잇기 고수사전」처럼
*한방단어 공략 앱*이 따로 장사가 될 만큼 있다. AI가 한방단어로 찍어눌러서 사람들이 진다.

> 사람들은 이기고 싶은 게 아니라 **아슬아슬하게 이기고 싶어한다.**

## 지금 상태

미니앱 이식 중. 서버도 API도 없이 완전 오프라인으로 돈다.

```
app/                   앱인토스 미니앱 (Granite WebView + Vite)
  index.html
  src/main.js          진입점 — 사전과 저장값을 먼저 받고 게임을 켠다
  src/game.js          게임 로직
  src/platform.js      토스 SDK 어댑터 (없으면 브라우저 폴백)
  src/style.css
  public/dict.json     사전 (빌드 산출물, 커밋 안 함)
  apps-in-toss.config.ts
index.html             단일 파일 프로토타입 (아티팩트용, 보존)
tools/build_dict.py    사전 빌드 — 위 둘에 모두 주입
docs/why-wordchain.md  왜 이 아이템인지
```

### 개발

```bash
cd app
npm install
npm run dev              # http://localhost:5173
npx ait build            # dist/ → wordbaduk.ait (배포 아티팩트)
npx ait token add        # 콘솔 API 키 등록 (최초 1회)
npx ait deploy           # 콘솔로 업로드
```

빌드 결과는 **1.0MB**(압축 전 2.5MB)다. 대부분이 사전이고 JS는 29KB다.

> ⚠️ CLI는 **3.x**라 설정 파일이 `apps-in-toss.config.ts`다.
> 문서에 보이는 `granite.config.ts`는 2.x 형식이니 헷갈리지 말 것.
> 2.x 프로젝트는 `ait migrate`로 변환한다.

**Node 설치 메모** — 이 맥은 Intel이라 Homebrew가 더는 바이너리를 주지 않는다(Tier 3).
nodejs.org 공식 tarball을 `~/.local/node`에 풀고 `/usr/local/bin`에 링크했다. 현재 v24.21.0.

`platform.js`가 SDK를 감싸고 있어서 **일반 브라우저에서도 그대로 열린다.**
토스 밖에서는 Storage가 localStorage로, 햅틱이 `navigator.vibrate`로, 리더보드가 no-op으로 떨어진다.

### 왜 WebView인가

Granite은 WebView SDK와 React Native SDK 두 갈래인데 WebView를 골랐다.
이 게임은 턴제 텍스트 UI라 네이티브 성능이 필요 없고, 이미 다듬어둔 DOM/CSS를 그대로 쓸 수 있다.
RN으로 가면 화면을 전부 다시 그려야 하는데 그만한 이득이 없다.

### 백엔드는 아직 없다

**리더보드는 토스가 전부 관리한다.** `Game.setLeaderboardScore`로 점수를 올리고
`openGameCenterLeaderboard`로 순위 화면을 여는 게 전부라, 우리 서버가 필요 없다.
점수 유효성만 게임 로직에서 책임진다.

서버가 필요해지는 건 토스가 안 해주는 것들이다 —
**도감 전국 달성률**(「히읗」을 찾은 사람이 몇 명인지), 기록 어뷰징 방어, 원격 설정(`AD_EVERY` 같은 값).
지금은 없어도 되고, 필요해지면 그때 올린다.

## 사전

| | 크기 | 출처 |
|---|---|---|
| 내가 쓸 수 있는 말 | **281,389** | 표준국어대사전 계열 표제어 366,505개에서 2~4음절·순한글·동사 제외 |
| 한글이가 아는 말 | **24,912** | 위 ∩ 명사 사전. 빈도순 3단(2,469 / 2,107 / 20,336) |
| 끝내는 글자 | **201** | 사전 전체에 이을 말이 없는 글자. 모을 만한 **28개**가 도감(1권 15 + 2권 13) |

도감 2권은 1권을 다 채워야 열린다. 1권은 흔한 말로 닿고(무슨·잔뜩·바깥·부엌·슬픔…),
2권은 명사로는 닿지만 흔하지 않은 것들이다(살갗·헝겊·펭귄·뒤꼍·남녘·그믐·수탉·히읗…).
나머지 173자는 고어·방언으로만 닿아서 수집 대상에서 뺐다 — 못 채우는 칸은 도감이 아니라 벽이다.

사전 라이선스는 CC BY-SA 계열이라 상업적 이용이 가능하다. 2차적저작물 배포 의무(SA)는
착수 전 한국저작권위원회 확인이 필요하다.

```bash
python3 tools/build_dict.py --dry-run   # 통계만
python3 tools/build_dict.py             # index.html에 주입
```

원천 데이터 3종은 `tools/data/`에 받아두며, 없으면 스크립트가 내려받는다.

## 설계

**난이도는 어휘가 아니라 결과를 조절한다.**
처음엔 난이도로 한글이의 어휘를 잘라봤더니 「스포츠」 한 번에 2수 만에 끝났다.
어휘 구멍으로 지는 건 실력이 아니라 사고다. 지금 한글이는 늘 24,912개를 다 쓰고,
난이도는 **어느 단의 말을 고를지**와 **말이 안 떠오를 확률**만 정한다.

**막히는 건 빡빡한 자리에서만.**
실제 국면의 62.8%는 둘 수 있는 말이 61개를 넘는다. 거기서 포기하면 그 자체가 들통난다.
그래서 막힐 확률에 자리의 빡빡함을 곱한다 — 4개 이하 ×1.0, 61개 이상 **×0**.
고친 뒤 실측하면 막힌 사건의 92%가 30개 이하 자리에서 일어난다.

**질 때는 고민한다.**
이길 때든 질 때든 620ms로 똑같이 두면 못 두는 순간만 도드라진다.
질 때는 반드시 2.7~4.2초 뜸을 들이되(「물」…「물」… 하고 되뇐다),
**오래 생각하고도 두는 경우가 더 많아야** 뜸들이기가 신호가 되지 않는다.
실측 기준 고민했을 때 지는 비율 11~31%.

**급수가 한글이의 바닥을 정한다.**
난이도가 승패만 따라 움직이면 오래 한 사람은 누구나 3단이 된다. 그런 급수는 자랑이 안 된다.
승급할 때마다 한글이가 내려갈 수 있는 바닥이 같이 오른다 — 18급 0.10 / 1급 0.65 / 3단 0.82.
곡선은 `0.10 + 0.72 × (급수/13)^1.6`. 어딘가에서 반드시 막히고, 막히는 자리가 곧 실력이다.

**끝까지 가면 무엇이 남는가.**
급수는 3단이 최고다(바둑처럼 9단까지 늘리지 않았다 — 200판짜리 그라인딩은 재미가 아니다).
최고 단에 닿으면 한글이의 바닥이 0.82로 고정돼 더는 물러서지 않고, 그 뒤의 목표는 셋이다 —
**도감 2권 13칸**, **최장 수순**(무한), **낯선 말**(사전 28만 중 한글이가 모르는 25만여 개).
승급이 끝나도 발견은 끝나지 않는 구조다.

**최장 수순은 랭킹을 위한 준비다.**
토스 SDK에 리더보드가 있지만 지금은 붙이지 않는다 — 출시 직후 빈 리더보드는 썰렁하고,
급수·도감이라는 축이 이미 둘 있다. 대신 **최장 수순**(한 판에서 몇 수까지 이었나)을 지금부터
로컬에 쌓아둔다. 당장은 자기 기록으로 작동하고, 나중에 랭킹을 붙일 때 그대로 지표가 된다.
닉네임도 **기록을 세운 뒤에** 묻는다 — 토스에 있는 경쟁 앱은 시작 전에 중복 검사를 시키는데,
설치가 없다는 미니앱의 강점을 스스로 버리는 구조다.

**비대칭이 재미다.**
한글이는 흔한 명사만 안다. 나는 사전 전체를 쓴다.
「담론」「성찰」처럼 한글이가 모르는 말을 두면 금색 돌로 놓이고 도감의 *낯선 말*에 쌓인다.
그 말로 길이 끊기면 그대로 이긴다. 일상어 기준 낯선 말이 뜨는 비율은 2%라 특별함이 유지된다.

## 광고

`ADS_DEFAULT = false`. 인앱 광고를 켜려면 사업자등록이 필요해서(누적 예상수익 5,000원까지 유예)
**꺼둔 채로 먼저 낸다.** 끄면 기능이 사라지는 게 아니라 무료가 된다.

| 자리 | 유형 | 켬 | 끔 |
|---|---|---|---|
| 힌트 (두 번째 글자) | 리워드 | 광고 3초 | 한 판에 1회 무료 |
| 진 뒤 무르기 | 리워드 | 광고 | 그냥 1회 |
| 판 사이 | 전면 | `AD_EVERY = 3`판마다 | 없음 |
| — | 배너 | 안 씀 (eCPM 꼴찌) | |

토스 문서 기준 eCPM은 **리워드 > 전면 > 배너**. 그래서 리워드에 무게를 싣고 전면은 드물게 둔다.
승급 시험과 첫 판에는 전면광고가 끼어들지 않는다.
